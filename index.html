Features

A complete engine, no strings attached

Everything here runs in your own infrastructure — the same code you can read, fork, and audit.

Universal data engine

One provider-agnostic Logical Query Plan compiled per connector — no provider-specific logic in the core.

Guardrails that bite

Read-only enforcement, SQL AST validation, injection detection, dialect-aware function checks — structurally, not optionally.

Four connectors

ClickHouse, PostgreSQL, MySQL, and SQLite — all live-verified, all on the same pipeline.

Audited by default

Who asked, which connection, which SQL, which decision — every step recorded and replayable.

Streaming + progress

Answers stream token-by-token with a live pipeline progress bar — no dead air, no spinners.

Evaluated regressions

A curated dataset scores validity, safety, execution, and latency on every change.

How it works

One deterministic pipeline

Question→ Schema discovery→ Logical plan→ Guardrails→ Audit→ Execute→ Mask→ Streamed answer

The planner proposes, deterministic validation disposes: wrong columns, unknown tables, or ClickHouse-only functions on PostgreSQL are rejected before any SQL runs — with an automatic retry loop, then a clarifying question.

Quick start

Running in minutes, not days

Docker (recommended)

# web · api · mcp · postgres · redis
git clone https://github.com/Abdul-Jaweed/DataHek-OSS.git
cd DataHek-OSS
cp .env.example .env
docker compose up -d --build
# → web UI on :5173 · API docs on :8000/docs

From source

python -m venv .venv && source .venv/bin/activate
pip install -e ".[all]"
uvicorn datahek.api.app:create_app --factory --port 8000
# configure your LLM endpoint in the web UI → Settings
