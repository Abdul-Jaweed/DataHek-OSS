01Why self-hosted

A data platform you can actually read.

I.

Read-only by construction

Write operations are denied at the plan layer — before any SQL exists. The guardrail is structural, not a setting.

II.

Trust nothing, verify

The model proposes a plan; deterministic validation disposes. Columns, tables, and dialect functions are checked against the real schema.

III.

No lock-in, no telemetry

One command to deploy, everything on your machine. Fork it, audit it, change it — the license allows all of it.

02How it works

One deterministic pipeline, from question to streamed answer.

Questionnatural language→ Schema discoveryper provider→ Logical planLLM proposes→ Validationschema · dialect · retry→ GuardrailsALLOW / DENY / MASK→ Executecompile → run→ MaskPII before reasoning→ Streamed answerSSE tokens → rows
01Question → schema discovery 02Logical plan (LLM) → validation 03Guardrails → execute → mask 04Streamed answer (SSE)

The planner gets one retry loop when validation fails — then it asks a clarifying question instead of guessing. Every decision lands in the audit trail, refusals included.

03Features

Everything here runs on your own hardware.

01

Universal engine

One provider-agnostic Logical Query Plan, compiled per connector — no provider logic in the core.core
02

Guardrails that bite

Read-only enforcement, SQL AST validation, injection detection, dialect-aware function checks.structural
03

Four connectors

ClickHouse, PostgreSQL, MySQL, SQLite — live-verified on the same pipeline.04 dialects
04

Audited by default

Who asked, which connection, which SQL, which decision — replayable end to end.jsonl
05

Streaming + progress

Tokens stream while a live progress bar shows each pipeline stage — no dead air.sse
06

Evaluated regressions

A curated dataset scores validity, safety, execution, and latency on every change.332 tests
07

Persistent by choice

PostgreSQL + Redis metadata with Fernet-encrypted credentials — or zero-config SQLite defaults.opt-in
08

Secrets where you keep them

DB credentials, login users, and LLM keys resolve from Infisical at runtime — never baked in.infisical

04Quick start

Running in minutes, not days.

docker — recommended
# web · api · mcp · postgres · redis
$ git clone https://github.com/Abdul-Jaweed/DataHek-OSS.git
$ cd DataHek-OSS
$ cp .env.example .env
$ docker compose up -d --build
✓ web ui → :5173 · api → :8000/docs
one command, everything included
from source
$ python -m venv .venv && source .venv/bin/activate
$ pip install -e ".[all]"
$ uvicorn datahek.api.app:create_app --factory --port 8000
# configure your LLM endpoint in the web UI → Settings
