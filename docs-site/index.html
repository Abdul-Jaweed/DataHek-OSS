What is DataHek

DataHek turns plain-language questions into safe, read-only data operations. The LLM proposes a structured query plan; deterministic code validates it, enforces guardrails, executes it on a physically read-only connection, masks sensitive columns, and audits every step. Answers stream back with a chart, a table, and a CSV export.

Quickstart

git clone https://github.com/Abdul-Jaweed/DataHek-OSS.git
cd DataHek-OSS
cp .env.example .env          # optional: LLM keys
docker compose up -d --build
✓ web :5173 · api :8000 · mcp :8001

Or from source (Python 3.12+):

python -m venv .venv && source .venv/bin/activate
pip install -e ".[all]"
uvicorn datahek.api.app:create_app --factory --port 8000

First steps

  1. Open the web app → Settings → enter your LLM base URL, API key, and model → Save.
  2. Connections → add a database (provider, host, port, database, credentials, SSL).
  3. Chat → ask: How many rows are in the traces table?
  4. Semantics → define metrics like error_count = count(*) where status = 'error'.
  5. Saved → save recurring questions and schedule them.
  6. Approvals → review gated exports and sensitive queries.

Guardrails

  • Input perimeter — injection/write-intent signatures, length, control characters (before the LLM)
  • Plan validation — tables, columns, joins, dialect function allowlists; one retry then clarification
  • Policy gate — allowlists, sensitive tables, unbounded exports → human approval; rate limits
  • Physical read-only — PG read-only transactions · SQLite mode=ro · MySQL read-only sessions · ClickHouse readonly=1 · DuckDB read_only=True
  • Output scanner — emails, phones, cards, SSNs, API keys, tokens, passwords, connection strings → redacted + audited

Connectors

ClickHouse, PostgreSQL, MySQL, SQLite, and DuckDB — all on the same LogicalPlan pipeline, all validated by the same guardrails. Adding a connector means implementing the provider contract; the engine never changes.

FAQ

Do I need an LLM?

For ask/chat, yes — any OpenAI-compatible endpoint. Guardrails, validation, execution and audit all work without a model.

Where does my data go?

Nowhere. Everything runs on your infrastructure; the only outbound calls are to the LLM endpoint you configure.

Can an injection write to my database?

No. Write plans are structurally impossible to compile, and the database connection itself is read-only — two independent layers reject it.
